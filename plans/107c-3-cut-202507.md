**작성 기준 커밋**: `26d0857` (2026-10-27) · 부모: `plans/107b-107c-window-cut-design.md` §2(절차 a~h) · 직전 달 `plans/107c-2-cut-202506.md`
**운영자 승인**: 2026-10-27 "권고대로 진행해줘 승인할게" — 권고 = **11-01 이후 사전 점검 재실측 → 계획자가 b·c·d·g → 삭제(e+f)는 운영자 SQL Editor**.
**왜 지금**: DB 합계 440.8MB(한도 500MB의 88%, 경보선 85% 초과). 자르기는 파일 크기를 줄이지 않고 원본 성장(월 ≈14MB)을 멈추는 것이 목적 — 이번이 세 번째 달이라 **자른 뒤 인덱스 회수(REINDEX)** 조건(3개월 이상)을 처음으로 채운다(§3 i).

## 0. 날짜 게이트
- 원본 이름 매칭 조회의 최대 창 = 15개월(`routes/transactions.js` 의 `monthsBack` ∈ {12, 15}).
- 2025-07 을 자르면 원본 시작 = 2025-08-01. 조건 `2025-08-01 ≤ 실행일 − 15개월` ⇔ 실행일 ≥ **2026-11-01**.
- 시간대: 적재 창 17:00~19:00 UTC · apt-master-sync 월요일 20:00 UTC · 이력 슬롯(19:20/21:20/…/13:20 UTC) 회피. 권장 **11-01~11-03 03:00 UTC 전후(12:00 KST)**.

## 2. 사전 점검 (전부 통과해야 c 로 간다) — 2026-10-27 실측 P2~P5 통과, P1 은 날짜 대기
```sql
-- P1 날짜: select now() >= '2026-11-01'::timestamptz;                                    -- true 여야 함 (10-27: false)
-- P2 연속성
select min(deal_date) from public.molit_transactions;                                      -- 2025-07-01
select max(deal_date) from public.molit_transactions_hist;                                 -- 2025-06-30
-- P3 이력에 7월이 없어야(두 번 넣으면 중복)
select count(*) from public.molit_transactions_hist where deal_date >= '2025-07-01' and deal_date < '2025-08-01';   -- 0
-- P4 apt_seq·dim
select count(*) filter (where apt_seq is null) from public.molit_transactions where deal_date >= '2025-07-01' and deal_date < '2025-08-01';  -- 0
select count(distinct t.apt_seq) from public.molit_transactions t
 where t.deal_date >= '2025-07-01' and t.deal_date < '2025-08-01'
   and not exists (select 1 from public.molit_apt_dim d where d.apt_seq = t.apt_seq);     -- 0
-- P5 그 달의 적재 구멍 0
select count(*) from (
  select distinct lawd_cd from public.molit_ingest_runs where status = 'ok' and deal_ym in ('202506','202508')
  except select distinct lawd_cd from public.molit_ingest_runs where status in ('ok','archived') and deal_ym = '202507'
) s;                                                                                        -- 0
```

## 3. 절차 (107c-2 와 같은 순서, 날짜만 7월) — SQL 파일 `supabase/migrations/20261101_107c3_cut_202507.sql`
- **b·c·d·g 는 계획자**(apply_migration·execute_sql — 함수 호출·INSERT 는 통과 실적: 2026-10-03 107c-2 b·c·g, 2026-10-27 함수 교체 3건).
- **e+f(삭제·archived)는 운영자 SQL Editor** — 삭제 문장은 Supabase 확인 단계에서 declined(10-03·10-27 실측). 확인을 피하려고 문장을 바꾸지 않는다.
- **i(신규) 인덱스 회수**: 세 달(2025-05·06·07)을 옮긴 뒤 `REINDEX INDEX CONCURRENTLY` — 대상 인덱스와 전후 크기는 실행 당일 `pg_relation_size` 로 잰다(쓰기와 측정은 별도 문장). 트랜잭션 밖이라 execute_sql, 거절되면 운영자.
