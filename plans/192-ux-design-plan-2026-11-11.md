# 192 디자인과 사용성 기획 (2026-11-11)

상태: 2026-11-11 운영자 승인("권고대로 진행"). 칩은 한 줄과 더보기, 결제 화면은 보류, 초안 페이지는 1단계 범위로 새로 씀.
이 문서의 숫자는 전부 2026-11-11 에 운영 화면과 코드에서 잰 값이다. 재지 못한 것은 "미확인"으로 적었다. 제안은 "제안"이라고 적었다.

## 1. 지금 서비스가 놓인 상황 (사실)

| 항목 | 값 | 출처 |
|---|---|---|
| 12시간 화면 조회 | 41회 | Vercel Web Analytics 수집 건수(관측 화면) |
| 오늘 방문, 누적 방문 | 23~24명, 198~199명 | 운영 화면의 방문 표시 |
| 하루 요청 약 5천 건의 주체 | Sentry 감시 봇 약 1,500, 링크 수집기 779, 네이버 550, 페이스북 미리보기 519, 구글 347 | Vercel 방화벽 트래픽 화면 |
| 화면 수 | 뷰 12개, 모달과 시트 16개 이상 | frontend/index.html 조사 |
| 첫 화면 파일 | 1.28MB (압축 406KB), 16,311줄 한 파일 | 파일 크기, 응답 헤더 |

읽는 법: 사람 방문은 아직 적고, 들어오는 길은 검색엔진과 공유 링크다. 그래서 디자인의 첫 목표는 "처음 온 사람이 첫 화면에서 바로 단지를 찾고 실거래를 본다"이다. 기능을 늘리는 것이 아니다.

## 2. 사용자가 하려는 일 (화면 구성에서 읽은 것)

1. 단지 이름이나 동 이름으로 찾아 실거래가를 본다. (검색, 지도, 단지 상세)
2. 요즘 거래가 많은 곳을 훑어본다. (첫 화면 목록, 브리핑)
3. 내 조건에 맞는 단지를 추린다. (목록, 보고서)
4. 계산하고 준비한다. (대출 계산, 갈아타기, 특약 초안, 청약 일정)

화면별 실제 사용 비율은 미확인이다. 2026-10-14 기록에 "화면별 사용량 데이터 없음"이라고 적혀 있고 지금도 같다. 그래서 아래 우선순위는 사용량이 아니라 "첫 화면에서 막히는 정도"를 기준으로 정했다.

### 3-6. 접근성과 일관성 (코드 집계)
- 누를 수 있는 div 와 span 이 120개, role=button 은 3개. 키보드로 누를 수 없다.
- 이름표 없는 아이콘 버튼 25개.
- 명암비 4.5 미달 회색: 98938A(3.05), 8A93A3(3.10), 8FA1B5(2.65), 결제 화면 8A98AC(2.68). 69707B 는 EFEFEB 위에서 4.33.
- 9~11px 글자가 지도 표식 등에 있다. 6단계 밖 글자 크기 선언 30개.
- 인라인 스타일 1,294곳, 직접 쓴 색 hex 379개, 모서리 32종, 그림자 63종.
- 처음 방문자용 모바일 소개 화면은 문제를 찾지 못했다.

## 4. 원칙 (제안)

1. 내용이 먼저다. 목록과 지도 같은 본 내용이 화면 세로의 60% 이상을 쓴다. 안내, 면책, 방문자 수는 한 줄로 모으거나 접는다.
2. 한 화면에 주 행동은 하나다. 같은 버튼을 두 번 두지 않는다.
3. 한 번 말한 것은 다시 말하지 않는다. 제목, 출처, 면책은 화면마다 한 번이다.
4. 오류와 빈 상태는 전용 모습으로 보여 준다. 정상 칸에 오류 문구를 넣지 않는다.
5. 모든 화면이 같은 토큰을 쓴다. 새 색과 새 글자 크기를 만들지 않는다.
6. 누를 수 있는 것은 버튼이다. 높이 44 이상, 초점 표시, 명암비 4.5 이상.
7. 절대 규칙은 그대로다. 매수와 매도 추천 없음, 가격 예측 없음, 출처와 면책 표시.

목록 한 행의 높이는 재지 못했다(미확인). 시안에서 64로 두면 415 안에 6행이 들어간다.

### 5-2. 모바일 지도 화면
- 시트 기본 높이에서 단지 3행이 보이게 한다. 칩은 한 줄, 보고서 버튼은 시트 맨 아래 한 번만.
- 지도 위에는 검색, 현재 위치성 버튼 묶음 하나, 채팅만 둔다. 안내문과 보고서 칩은 뺀다.
- 지도 버튼 묶음은 이름표와 테두리가 한 덩어리로 보이게 정리한다.

### 5-3. 단지 상세
- 이름은 머리에 한 번. 본문 첫 줄은 지역과 평형 요약으로 쓴다.
- 창 높이를 화면의 90%까지 쓴다(709 화면에서 내용 창 약 560).
- 탭 7개는 유지하되 머리 아래에 붙여 둔다. 탭 수를 줄이는 것은 사용량을 재고 나서 정한다(지금은 근거 없음).

### 5-4. 오류와 빈 상태
- 단지를 못 찾은 링크: 제목 "단지를 찾지 못했어요", 이유 한 줄, 검색창으로 가는 버튼 하나. 탭과 "다음에 할 일"은 숨긴다.
- 같은 틀을 조회 실패, 결과 없음, 한도 초과에도 쓴다.

### 5-5. 테마 통일
- 약관, 개인정보, 환불, 404, 브리핑 강조색을 v2 토큰으로 맞춘다. 문구는 건드리지 않는다.
- 서버 렌더 페이지: 글꼴 이름을 앱과 맞추고, 다크는 기기 설정을 따르는 지금 방식을 유지한다(앱의 전환 값을 서버가 알 수 없다).
- 결제 화면은 운영자가 결제 주제를 꺼내기 전에는 바꾸지 않는다는 기존 결정이 있다. 색만 맞출지는 6절에서 묻는다.

### 5-6. 접근성 (모양은 그대로, 시안 불필요)
- 누를 수 있는 div 와 span 120개를 button 으로 바꾸고 이름표를 단다.
- 미달 회색 네 가지를 4A515C 또는 69707B 로 바꾼다. EFEFEB 위의 작은 글자는 4A515C 를 쓴다.
- 9~11px 글자는 12 이상으로 올린다(지도 표식 포함).

## 6. 순서와 범위 (제안)

| 단계 | 내용 | 시안 필요 | 끝났다고 보는 기준 |
|---|---|---|---|
| 1 | 첫 화면(데스크톱, 모바일), 단지 상세, 오류 상태 | 예. 이 네 화면만 | 1440x709 에서 목록 5행 이상과 지도 540 이상, 375x812 에서 목록 3행 이상, 같은 버튼 중복 0, 상세 이름 1회 |
| 2 | 테마 통일(약관, 개인정보, 환불, 404, 브리핑 강조색, 서버 렌더 글꼴) | 작게. 색 대응표로 충분 | 직접 쓴 옛 색 0, 명암비 4.5 이상 |
| 3 | 접근성 | 아니오 | 누를 수 있는 div, span 0. 이름표 없는 아이콘 버튼 0 |
| 4 | 코드 정리(인라인 스타일, 직접 쓴 색, 모서리와 그림자 종류) | 아니오 | 화면 모습 변화 0 을 화면 비교로 확인 |

단계마다 구현 뒤 같은 방법으로 다시 재서 표의 기준을 숫자로 확인한다.

## 7. 운영자가 정할 것

1. 이 방향으로 1단계 시안을 만들지.
   - 쓰임: 승인하면 "내집로그 전면 리디자인"에 네 화면 시안을 Fable 5.2 로 만든다.
   - 바뀌는 것: 첫 화면에서 동기화 띠, 지도 위 기능 링크, 방문자 표시의 자리가 바뀐다.
2. 지역 칩을 사양대로 4개로 할지, 지금처럼 전부(10개) 한 줄에 두고 넘치면 "더보기"로 할지.
   - 권고: 한 줄에 들어가는 만큼 보이고 나머지는 더보기. 데이터가 있는 시도를 숨기지 않는다.
3. 결제 화면의 색을 2단계에 넣을지.
   - 넣으면: 금색이 남색으로 바뀐다. 결제 동작과 보안 설정은 건드리지 않는다.
   - 권고: 결제를 열 때 함께 한다(지금은 보류).
4. Claude Design 에 생긴 미완성 초안 "내집로그 개선 3차"를 어떻게 할지.
   - 2026-11-11 에 기획 전에 요청이 나가 중간에 멈춘 초안이다. 기존 v2 페이지는 바뀌지 않았다.
   - 권고: 승인 뒤 이 초안을 이어서 쓰지 않고 1단계 범위로 새로 요청한다. 초안은 지운다.
