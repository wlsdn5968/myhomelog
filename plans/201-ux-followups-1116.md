# 201. 시나리오 점검에서 남은 네 가지 (기획 문서, 운영자 승인 대기)

작성 2026-11-16. 근거는 2026-11-15 운영 크롬 점검(`AUDIT_REPORT.md` 13절)과 그날 읽은 코드다. 이 문서는 시안과 구현 전에 운영자 승인을 받기 위한 것이다(저장소 규칙: 시안 요청 전에 기획 문서 승인이 먼저). 아직 아무것도 구현하지 않았다.

공통 원칙
- 매수와 매도 추천, 가격 예측은 하지 않는다. 면책 문장과 법적 고지는 글자 그대로 둔다.
- 화면 문구는 해요체, 문장 속 화살표와 줄표 나열 금지, 내부 용어 금지.
- 새 요청이나 무거운 계산을 늘리지 않는다(Vercel CPU 30일 누적 한도).

## 1. 도우미가 예산 질문에 막다른 답을 한다

지금(확인됨)
- "9억으로 서울에서 살 수 있는 아파트 알려줘"에 "그 질문은 제가 가진 공식 데이터로는 정확히 답하기 어려워요"와 예시 질문만 돌아온다(`backend/services/chatDataRouter.js` 837줄 부근의 미매칭 답).
- 같은 일을 하는 화면이 이미 있다. 목록 화면은 예산과 지역으로 단지를 찾는다(같은 조건에서 806건).

바꿀 안(권고)
- 질문에 금액(억)과 "살 수 있는, 살만한, 예산, 얼마로" 같은 말이 함께 있으면 답 끝에 단추 하나를 붙인다. "9억, 서울 조건으로 목록에서 찾기". 누르면 목록 화면으로 가서 매수 예정가와 지역을 채우고 찾는다.
- 답 문장은 "예산으로 단지를 고르는 일은 목록 화면에서 할 수 있어요. 매물 추천은 하지 않고, 실거래 기준으로 조건에 드는 단지를 정리해 드려요."
- 도우미가 직접 단지를 골라 답하지는 않는다. 추천으로 읽히지 않게 하고, 도우미 한 번에 무거운 조회가 붙지 않게 하기 위해서다.

대안
- 도우미가 목록 조회를 직접 불러 상위 5곳을 답 안에 보여 준다. 편하지만 조회가 무겁고(운영 실측 9.9초) 추천으로 읽힐 위험이 크다. 권하지 않는다.

시안: 필요 없음. 기존 답 말풍선에 기존 단추 모양 하나가 붙는다.
규모: 작음. 서버 의도 판정 한 갈래와 화면 단추 처리, 검사.

## 2. 맞춤 보고서가 돈이 모자란 것을 말하지 않는다

지금(확인됨)
- 매수가 9억, 자기 자본 0억으로 보고서를 만들면 본문 어디에도 부족 자금 안내가 없다(본문에 "부족" 글자 0건). 같은 값으로 대출 계산은 "LTV 한도 3.60억, 부족 자금 5.40억"이라고 알려 준다.
- 실제 단지 목록은 출처 목록, 한 구의 미분양과 거래량, 정책, 체크리스트 뒤에 나온다. 화면 높이 5,429px 가운데 한참 아래다.
- 9억 조건에 10.20억 단지가 "예산 매칭"으로 들어 있다. 예산 범위를 어떻게 잡는지(위로 얼마까지) 화면에 설명이 없다.

바꿀 안(권고)
- 본문 맨 위 요약에 한 줄을 넣는다. "매수가 9억이면 대출 한도는 최대 3.60억쯤이에요(무주택, 규제지역 LTV 40% 기준). 자기 자본이 5.40억보다 적으면 돈이 모자라요. 지금 입력한 자기 자본은 0억이에요." 숫자는 대출 계산과 같은 식(`calcLTV`)에서 가져와 두 화면의 숫자가 같게 한다.
- 순서를 바꾼다. 요약, 조건에 드는 단지 목록, 그다음 지역 통계와 정책과 체크리스트, 맨 끝에 출처.
- 예산보다 비싼 단지가 들어가는 기준을 한 줄로 적는다(실제 기준은 구현 전에 코드에서 확인해 그대로 적는다. 지금은 확인 불가).

대안
- 자기 자본이 한도에 못 미치면 생성 전에 막는다. 막다른 길이 되므로 권하지 않는다. 알려 주고 만들게 한다.

시안: 필요. 순서와 요약 상자의 모양이 바뀐다. Claude Design 에서 보고서 화면 1장(데스크톱과 모바일).
규모: 중간.

## 3. 비교 담기 막대가 모든 화면을 따라다닌다

지금(확인됨)
- 목록에서 단지를 비교에 담으면 화면 아래 가운데에 "비교 담기 2/6, 단지 비교 보기, 비우기" 막대가 뜬다(`.cmp-bar`, 고정 위치).
- 이 막대가 보고서, 청약, 특약, 체크리스트, 갈아타기, 브리핑 화면에도 그대로 떠서 아래쪽 내용과 단추를 가린다.

바꿀 안(권고)
- 막대는 목록 화면과 지도 화면에서만 보인다. 다른 화면에서는 숨기고, 담아 둔 단지는 그대로 둔다(돌아오면 다시 보인다).
- 단지 상세가 열려 있을 때의 기존 위치 규칙은 그대로 둔다.

대안
- 모든 화면에서 작게 접어 오른쪽 아래 단추 옆에 숫자만 보인다. 담은 것을 잊지 않게 하지만 떠 있는 단추가 하나 더 는다.

시안: 필요 없음(권고안). 보이는 화면만 바뀐다.
규모: 작음.

## 4. 단지 상세의 가격 신호 탭이 어렵고 숫자가 달라 보인다

지금(확인됨)
- "시세 위치 요약: 1/3개 데이터 부합", "최근 3개월 거래 증가 (성수기 영향 감쇄)", "층·향(RR/저층)" 같은 말이 그대로 나온다(`frontend/index.html` 10826줄 부근, `backend/services/analysisService.js` 287줄과 352줄).
- 상세 머리의 평균은 31.38억(77㎡ 최근 20건)인데 이 탭의 매매가는 32.29억이다. 기준(평형, 기간)이 달라서인데 화면에 설명이 없다.
- 같은 단지가 목록에서는 "6개월 가중 평균", 비교 창에서는 "12개월 중앙값", 구 순위에서는 "60일 평균"으로 나와 숫자가 서로 다르다.

바꿀 안(권고)
- 말만 먼저 고친다. 계산은 건드리지 않는다.
  - "1/3개 데이터 부합"은 "세 가지 가운데 한 가지가 해당돼요"로 바꾸고, 세 가지가 무엇인지(가격 위치, 거래량, 전세가율) 바로 아래에 해당 여부와 함께 적는다.
  - "성수기 영향 감쇄"는 "이사철(3, 4, 9, 10월)이 끼어 있어 실제보다 많아 보일 수 있어요"로.
  - "RR/저층"은 "같은 평형이어도 층과 방향에 따라 값이 달라요"로.
- 숫자 옆에 기준을 붙인다. 예: "32.29억 (전체 평형, 최근 6개월 46건)". 머리의 31.38억 옆 설명(77㎡, 최근 20건)은 지금도 있다.
- 화면마다 다른 평균(가중 평균, 중앙값, 60일 평균)을 하나로 합치는 일은 이번에 하지 않는다. 계산 규칙을 바꾸는 큰 일이고 각 화면의 기준에는 이유가 있다(`docs/ops/feature-history.md`). 이번에는 기준을 적어 다르다는 것을 알 수 있게만 한다.

대안
- 탭 구성을 다시 짠다(요약 한 장과 자세히 보기). 효과는 크지만 큰 개편이라 따로 시안과 계획이 필요하다.

시안: 권고안(말만 고침)은 필요 없음. 문구 대조표를 구현 전에 운영자에게 보여 준다. 탭 구성을 다시 짜려면 시안 필요.
규모: 권고안 작음에서 중간(문구를 맞춰 보는 검사가 여럿 있다).

## 순서안

1. 3번(막대)과 1번(도우미 단추): 작고 시안이 필요 없다. 승인되면 바로 구현.
2. 4번 권고안: 문구 대조표를 먼저 보여 드리고 승인되면 구현.
3. 2번(보고서): 시안을 만들어 승인받은 뒤 구현.

- 1번: 권고안(목록으로 넘기는 단추)으로 갈지, 대안(도우미가 직접 5곳을 답)으로 갈지.
- 2번: 순서 바꾸기와 부족 자금 안내를 진행할지. 진행하면 시안부터 만든다.
- 3번: 막대를 목록과 지도 화면에서만 보일지, 모든 화면에서 작게 접을지.
- 4번: 말만 고칠지, 탭 구성까지 다시 짤지.
