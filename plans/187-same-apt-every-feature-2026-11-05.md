# 187 같은 단지가 기능마다 다르게 보이는 문제 전수조사 (2026-11-05)

운영자 실측: 관심 단지로 연 공릉풍림아이원의 헤더는 8.12억인데 실거래 탭은 "최근 거래 0건", "예전 거래를 불러오지 못해", "분석 대기".

## 방법
- 단지 상세 진입 경로 전수(frontend/index.html)와 서버의 단지-거래 조회 전수(backend)를 sonnet 에이전트로 조사했다.
- 지적은 운영 API, 운영 DB, 운영 화면으로 재현한 것만 고쳤다. 재현되지 않은 지적은 뺐다.

## 근본 원인
단지 상세로 가는 길이 셋이었다. 거래를 받아 오는 openAptDetail, 목록 항목을 그대로 넘기는 showDetail, 거래를 비운 채 여는 관심 단지. 같은 단지가 어디서 여느냐에 따라 달랐다.

## 고친 것
| 문제 | 재현 | 수정 |
|---|---|---|
| 관심 단지가 거래 없이 열림 | 헤더 8.12억, 탭 0건 | openAptDetail 로 연다. 동까지 비교한다. 운영 확인: 관심 단지와 검색 모두 8.12억, 27건, 준공 2001 |
| 지역 영역 항목, 맞춤 목록, 지도 더블클릭, 공유 링크 | 코드 확인 | `_openProp` 입구로 통일. 공유 링크의 자체 평균 계산 제거 |

| 호출자가 준공 연도를 안 넘기면 준공 칸과 재건축 표시가 사라짐 | 코드 확인 | 받아 온 거래에서 채운다 |

| 이너스내안에에 다른 단지가 섞임 | 254-2번지 2004(공식 일치), 307번지 2011 | 연도 별칭(override 2건). 운영 확인 |
| 도우미가 시군구 전체를 세고 6개월 시작일이 다름 | 코드 확인 | 같은 동, 같은 창 |
| 지도 기간이 다름 | 공릉풍림아이원 지도 37건, 상세 27건 | 지도도 6개월 창. 팝업 라벨 "전 평형 평균" |
| 도우미 평균 방식이 다름 | 도우미 7.91억, 상세 8.12억 | 상세와 같은 대표 평형 규칙 |
| 단지 페이지가 신고 이름 하나만 셈 | /apt/11350-183 제목은 공식 단지, 거래는 A만 123건, B동 31㎡ 누락 | 같은 공식 단지의 신고 번호를 합친다 |
| 라벨과 실제 범위가 다름 | 평형별 평균 (30건), 층 분포 "최근 6개월" | "최근 N건"으로 표기 |

## 재현되지 않아 고치지 않은 지적
- 별칭 병합의 중복 제거가 다른 거래를 합친다: 최근 180일 해당 0건.
- /api/transactions/history 400: 조사 때 공식 단지 코드를 넣은 시험 오류. 화면은 신고 번호로 호출한다.

## 남은 것
1. 지도 팝업의 "전 평형 평균"과 상세의 "대표 평형 평균"은 기준이 달라 값이 다르다(공릉풍림아이원 약 7.9억과 8.12억). 지도를 대표 평형으로 바꾸려면 영역 집계를 평형별로 내야 한다.
2. 인기 단지 집계는 DB 함수가 신고 이름별 상위만 준 뒤 별칭을 합쳐, 순위 밖 신고 이름이 빠질 수 있다. DB 함수 변경이 필요하다.
3. 등록 뒤 해제된 거래가 DB에 남은 수는 미확인. 일일 적재가 최근 3개월만 다시 받는다.
4. 유지 점검 값(11-05): 손 보정 93행(10-31과 같음), 별칭 보정 누락 0건, 잠금 트리거 켜짐.
