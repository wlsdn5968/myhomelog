# 166 — 첫 사용자 관점 기능·UX 제안 (2026-10-18, 운영자 결정 대기)

운영자 요구: "사용자가 바로바로 볼 수 있고 UX 가 가장 편해야 쓴다. 한 방에 다 하지 말고 크롬으로 하나하나 보면서 있으면 좋을 기능(카톡·텔레그램 연동, 동반자, 공유해서 바로 보기 등)을 제안하라. 괜찮은 것만 추출."
근거: 운영자 크롬(로그인 상태, 1440px)에서 실제 사용 + 코드 전수 목록화(sonnet, 파일:줄) + 계획자 코드 재대조. 추정은 "추정"으로 표시.

## 1. 오늘 실제로 써 본 결과
- 첫 화면: 인기 단지 칩이 전국·경기·인천·부산뿐(서울 없음 — 인기 API 상위 12곳에 서울이 없어서). 서울 사용자는 첫 화면에서 자기 지역을 고를 수 없다.
- 검색: "은마" 입력 → 자동완성 10건(동명 단지 구분 표시 좋음). 결과 도착 전 Enter 는 아무 반응 없음(도착 뒤 Enter 는 첫 결과 상세 열림 — 코드 `onHeaderSearchKey`). "잠실주공" 0건은 DB 에 그 이름 거래가 없어서(데이터).
- 단지 상세: 탭 7개(종합의견·실거래가·위험·특약 초안·가격 신호·단지 정보·임장노트), 하단 "다음에 할 일" 10가지. 정보량은 충분.
- 목록 화면 사이드바 "내 상황" 3단계 폼이 보고서 화면의 3단계 폼과 사실상 같다(두 곳에 같은 입력).
- 관심 단지 패널에 이미 있는 것: 새 거래 푸시 알림, 카카오톡(나와의 채팅) 알림, 목표가 설정, 메모, 비교 체크.
- 알림 센터: 카카오톡 알림·브라우저 푸시·발송 미리보기·대상 단지(최대 30).
- 로그인 사용자는 `/api/health` 를 부팅 12초 안 5회, 7분간 13회 호출(로그인 분기가 공유 캐시를 우회 — index.html refreshQuota). health 1회 = Redis 명령 8개.

## 3. 제안 (괜찮은 것만)
### 3-1. 바로 고칠 것 (결함·사실 불일치, 각 S)
1. 임장 노트 받아오기(A1) — 상세 열 때 `GET /api/field-notes/:aptName` 로 서버 값 병합. 안 하면 문구를 바꿔야 함.
2. 알림 도착지(A2) — 단지 1곳이면 `/?apt=&area=` 딥링크, 여럿이면 `/?view=list`(관심 목록). sw.js 는 열린 창에 `navigate` 또는 `postMessage`.
3. 공유 미리보기(A3) — `/share?apt=` 에 aptSeq 가 있으면 `og:image` 를 단지 OG 로 치환.
4. 검색 이력 눌러 재검색(A4) · 비교 담기 세션 유지(A5) · Enter 대기 안내(A8).

### 3-2. "공유해서 바로 같이 보기" (동반자 기능, 계정 불필요 — M)
- **관심 목록 링크**: 비교 링크(`/share?cmp=`, 2~6곳)와 같은 방식으로 관심 단지 묶음(최대 30)을 URL 에 담아 `/share?list=` — 받는 사람(가족·배우자)이 로그인 없이 같은 목록·가격을 봄. DB 변경 없음.
- **카카오톡 공유 버튼**: 지금은 OS 공유창/클립보드뿐. 카카오 JS SDK `Kakao.Share`(무료, 도메인 등록 필요)로 단지·비교·목록 링크를 카톡 메시지 카드로 보냄 — OG 이미지(3-1-3)와 함께 효과 큼. CSP `script-src` 에 developers.kakao.com 추가 필요.
- (보류) 실시간 공동 편집·댓글: 사용자 7명·30일 로그인 0 상황에서 DB 테이블·권한 설계 비용 대비 근거 부족.

### 3-3. 알림을 "원하는 것"으로 (M)
- 목표가 도달 알림을 서버 발송에 포함(A6): 목표가를 서버 북마크에 저장하고 push-notify cron 이 비교. 매일 1회 묶음이라 비용 증가 없음. DB: bookmarks 에 목표가 열 추가 필요(운영자 승인).
- 단지별 알림 켬/끔(지금은 관심 단지 전체).
- (보류) 텔레그램: 무료지만 카카오 나와의 채팅이 이미 있고 사용자 근거 없음. 요청이 생기면 pushNotify 에 채널 하나 추가하는 구조(S~M).

### 3-4. 첫 화면·흐름 (시안 필요 — 운영자 상시 요구 "Claude Design 시안 먼저")
- 인기 칩에 서울 포함(인기 API 에 지역 조건 추가 → 칩 고정 목록 + 지역별 상위). 지금은 서울 사용자가 첫 화면에서 자기 지역을 못 고름.
- 목록 사이드바 폼과 보고서 폼 통합(같은 입력이 두 곳): 한 번 입력하면 목록·보고서가 같은 값을 쓰도록 — IA 재편이라 시안·운영자 결정.
- 지도 화면에서도 관심 단지 관리 가능하게(A7): FAB 팝오버에 알림 토글·목표가 노출 또는 패널로.

### 3-5. 비용·안정 (S)
- 로그인 사용자 health 중복 호출 줄이기: 인증 응답도 20초 공유 캐시 적용(토큰 있을 때 별도 캐시 키). Redis 명령·DB 조회 절감. 근거: 부팅 12초 안 5회 실측.

## 4. 하지 않을 것
- Go/No-Go·매수 신호(절대 룰 위반) · 유료 서비스(텔레그램 유료 플랜, 카카오 알림톡 등) · 과도한 온보딩 팝업.
