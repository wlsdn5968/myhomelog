## 0. 날짜 게이트 — 왜 오늘(09-27)은 안 되나 (식)
- 이름 매칭 조회의 최대 창 = 15개월: `backend/routes/transactions.js:43` 이 `monthsBack` 을 `['12','15']` 만 허용하고, `getTransactionsByApt` 가 `now − monthsBack` 부터 원본을 읽는다.
- 2025-06 을 자르면 원본 시작 = 2025-07-01. 조건: `2025-07-01 ≤ 실행일 − 15개월` ⇔ 실행일 ≥ **2026-10-01**.
- 09-27 에 자르면 창 = 2025-07-01 ~ 2026-09-27 = **14.9개월** → 15개월 조회가 2025-06-27~30 을 놓친다(부적합).
- 권장 10-27: 창 = 2025-07-01 ~ 2026-10-27 = 15.9개월(107c-1 직후와 같은 여유), 월 1회 리듬.
- 시간대: 적재 창 17:00~19:00 UTC · apt-master-sync 월요일 20:00 UTC · 이력 슬롯(19:20/21:20/…/13:20 UTC) 을 피한다. 107c-1 은 03:0x UTC 에 했다.

## 2. 사전 점검 (전부 통과해야 c 로 간다)
```sql
-- P1 날짜: select now() >= '2026-10-01'::timestamptz;                         -- true
-- P2 연속성: 원본 시작이 정확히 6월, 이력 끝이 정확히 5월
select min(deal_date) from public.molit_transactions;                          -- 2025-06-01
select max(deal_date) from public.molit_transactions_hist;                     -- 2025-05-31
-- P3 이력에 6월이 없어야(유일 제약 없음 — 두 번 넣으면 중복)
select count(*) from public.molit_transactions_hist where deal_date >= '2025-06-01' and deal_date < '2025-07-01';   -- 0
-- P4 apt_seq·dim
select count(*) filter (where apt_seq is null) as null_seq, count(*) as rows
  from public.molit_transactions where deal_date >= '2025-06-01' and deal_date < '2025-07-01';                      -- null_seq 0
select count(distinct t.apt_seq) from public.molit_transactions t
 where t.deal_date >= '2025-06-01' and t.deal_date < '2025-07-01'
   and not exists (select 1 from public.molit_apt_dim d where d.apt_seq = t.apt_seq);                               -- 0
-- P5 (신규, 2026-09-27 발견 반영) 그 달의 적재 구멍 0: 앞뒤 달에 정상 적재가 있는 지역은 M 에도 ok 가 있어야 한다.
--    구멍이 있는 달을 자르면 archived 가 재시도를 영구히 막아 이력에 구멍이 굳는다.
select count(*) from (
  select distinct lawd_cd from public.molit_ingest_runs where status = 'ok' and deal_ym in ('202505','202507')
  except select distinct lawd_cd from public.molit_ingest_runs where status in ('ok','archived') and deal_ym = '202506'
) s;                                                                                                               -- 0
```

## 3. 절차 (107c-1 과 같은 순서, 날짜만 6월)
```sql
-- b. 경신 기준선 합산 (단독 문장) → 반환값 기록. 행수는 **별도 문장**으로 전후 측정.
select public.upsert_hist_peaks_for_month('202506');
select count(*) from public.molit_hist_peaks;                                   -- 81,918 → 증가 확인

-- c. 이력 복사 — apply_migration 이름 20261027_107c2_copy_202506_to_hist (실행일로 바꾼다)
insert into public.molit_transactions_hist (apt_seq, deal_date, exclu_use_ar, deal_amount, floor)
select t.apt_seq, t.deal_date,
       least(round(t.exclu_use_ar * 100), 32767)::smallint,
       t.deal_amount,
       least(greatest(coalesce(t.floor, 0), -32768), 32767)::smallint
  from public.molit_transactions t
 where t.deal_date >= '2025-06-01' and t.deal_date < '2025-07-01' and t.apt_seq is not null;

-- d. 대조 (별도 문장) — 셋 다 같아야 e 로 간다. 다르면 STOP, 이력 쪽만 되돌리고 원인 조사.
select (select count(*) from public.molit_transactions where deal_date >= '2025-06-01' and deal_date < '2025-07-01') as live_rows,
       (select count(*) from public.molit_transactions_hist where deal_date >= '2025-06-01' and deal_date < '2025-07-01') as hist_rows,
       (select sum(deal_amount) from public.molit_transactions where deal_date >= '2025-06-01' and deal_date < '2025-07-01') as live_sum,
       (select sum(deal_amount) from public.molit_transactions_hist where deal_date >= '2025-06-01' and deal_date < '2025-07-01') as hist_sum;
-- 양방향 차집합 (apt_seq, deal_date, 면적×100, 금액) 0/0
select count(*) from (
  select apt_seq, deal_date, least(round(exclu_use_ar*100),32767)::smallint a, deal_amount from public.molit_transactions
   where deal_date >= '2025-06-01' and deal_date < '2025-07-01'
  except all
  select apt_seq, deal_date, exclu_use_ar, deal_amount from public.molit_transactions_hist
   where deal_date >= '2025-06-01' and deal_date < '2025-07-01') x;           -- 0 (반대 방향도 0)

-- e+f. 삭제 + archived — apply_migration 이름 20261027_107c2_delete_202506_from_live
delete from public.molit_transactions where deal_date >= '2025-06-01' and deal_date < '2025-07-01';
update public.molit_ingest_runs set status = 'archived'
 where deal_ym = '202506' and status in ('ok','error','skipped','timeout');

-- g. 단독 문장(refresh 와 select 를 한 문장에 넣으면 55006) · VACUUM 은 트랜잭션 밖(execute_sql)
select public.refresh_molit_apt_index();
vacuum (analyze) public.molit_transactions;
```
