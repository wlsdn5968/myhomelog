## 151 — 첫 화면 구조 (원래 기록)
시안 화면 B: 데스크톱 = 헤더 64 + 왼쪽 패널 420(최근 거래가 많은 단지 목록 + 지역 필터 + "내 조건으로 맞춤 보고서 받기" 주 버튼) + 오른쪽(검색창 56 + "다른 기능도 있어요" 텍스트 버튼 4 + 지도). 모바일 = 검색 48 + 기능 버튼 가로 스크롤 + 지도 위 목록 시트 + 하단 탭 5. **"내 상황 입력"은 첫 화면에서 빼고 보고서 화면으로**.
확인된 사실(구현 전 반드시 반영):
- 왼쪽 목록 데이터 = `/api/search/popular` 응답 `results[]`: `aptSeq, aptName, displayName, lawdCd, sigungu, umdNm, lat, lng, buildYear, dealCount60d, avgDealAmount(만원, 60일 평균), recentDealDate` (2026-10-15 실측). **"최근 거래가"(가장 최근 단건 가격) 필드는 없다** → 칸 이름을 "60일 평균가"로 표기하거나 서버에 필드를 추가해야 한다(지어내지 말 것).
- 위저드(내 상황)는 이미 `_wizPlace(v)` 가 뷰에 따라 노드를 옮긴다(보고서 화면에서는 본문으로 이동) — 151 은 지도·목록 화면 사이드바에서 빼는 작업. 사이드바의 관심 단지·계약 타임라인·규제 표 행선지도 정해야 한다(시안에 없음 → 계획에서 결정).
- `searchWithBudget`·`/?region=` 자동 검색(Plan 148)·사이드바→계산기 값 이어 주기가 사이드바 입력칸(#bp #mc #inc, 칩 ch-h/ch-f/ch-r)에 의존 — 옮길 때 같이 고칠 것.
- 계약 테스트 다수가 사이드바 구조를 찾는다(frontend-contracts 등) — 테스트 의도 유지하며 갱신.
권장 순서: (1) 하위 에이전트로 사이드바·위저드·인기 목록 의존 관계 조사(읽기 전용) → (2) 151 계획서 → (3) 후보 구현 → (4) 미리보기 데스크톱·모바일 실측 → (5) 운영.
