# 203. 정책 변화 한 장 요약 (구현 끝, 미배포)

작성 2026-11-16. 운영자 요청(원문): "정책 브리핑이나 국토교통부 관련 자료들이 나오면 쉽게 설명해주고, 어떤것들이 바뀐다. 예를 들면 지금은 어떤데 -> 바뀌면 이렇다 이런식으로 한장 요약 수준으로 좀 요약해주면 좋겠거든? 25년부터 26년 현재까지 나온 규제, 부동산 관련 제도 변화, 등등 정부나 국토교통부 관련 자료들 다 모아서 날짜별로 규제사항들 한장 요약을 해줄수 있으면 사람들도 보기 편하고 좋을거 같긴하거든?"

## 지금 무엇이 부족한가

- 날짜순으로 정책을 보여 주는 곳은 대출 계산 화면 안의 타임라인 하나이고 10줄이다. 2025년 10월 15일 이전 것은 없다.
- 규제 요약 창은 지금 기준만 보여 준다. 무엇이 무엇에서 바뀌었는지는 보이지 않는다.
- 전월세, 청약, 세금 쪽 변화는 어디에도 없다.

## 무엇을 만드는가

화면 이름은 "정책 변화". 한 줄 설명은 "정부 발표로 무엇이 어떻게 바뀌었는지 날짜순으로 모았어요".

1. 맨 위 요약 띠: 마지막으로 원문을 확인한 날, 모은 건수, 가장 최근 변화 3건.
2. 분류 단추: 전체, 대출, 규제지역과 토지거래허가, 세금, 청약과 공급, 전월세.
3. 상태 단추: 전체, 시행 중, 예정과 정부안, 끝난 것.
4. 날짜순 카드(최신이 위). 카드 한 장에 담는 것
   - 발표일, 기관, 분류, 상태 표시(시행, 예정, 정부안, 계획, 끝남)
   - 제목(쉬운 말)
   - "지금까지"와 "바뀐 뒤" 두 칸. 원문에 바뀌기 전이 없으면 "바뀐 뒤"만 보인다.
   - 누구에게 해당하는지
   - 덧붙임(뒤에 다시 바뀐 것, 시행일을 찾지 못한 것 등)
   - 원문 링크(정책브리핑, 금융위, 법령)와 확인한 날
5. 연도 구분선(2026, 2025)과 달 표시.
6. 맨 아래 고지: 참고용 정리이며 실제 적용은 원문과 담당 기관에서 확인, 매수와 매도 추천이 아님.

들어가는 길: 위쪽 도구 메뉴의 "규제 요약" 옆에 "정책 변화", 브리핑 화면 세 번째 줄의 링크, 대출 계산의 타임라인 자리(타임라인은 최근 3건만 남기고 "전체 보기"로 연결), 주소 `?view=policy`.

검색에 잡히게 서버가 만드는 페이지 `/policy` 도 둔다. 브리핑과 지역 페이지가 쓰는 방식 그대로이고, 자료는 같은 파일을 읽는다. 사이트맵에 넣는다.

## 자료

- 초안: `plans/203-policy-changes-data.json`. 2025년 2월부터 2026년 10월까지 38건.
- 모은 방법: 기간을 셋으로 나눠 낮은 등급 에이전트가 정책브리핑, 금융위, 국토교통부 목록을 달마다 훑었다(후보 약 76건). 그 가운데 정책브리핑과 금융위 페이지 42개를 2026-11-16 에 직접 받아 대조했다.
  - 에이전트 인용 78개 가운데 77개가 원문에 그대로 있었다. 어긋난 1개(매입임대 중과 배제 기한의 날짜)는 자료에서 날짜를 뺐다.
  - 세부 숫자 77개 가운데 66개가 원문에 있었고 나머지는 자료에 쓰지 않았다.
  - 자료 초안의 숫자 104개를 출처 원문과 기계 대조했다. 못 찾은 15개는 모두 날짜 적는 방식 차이였다.
- 넣지 않은 것은 같은 파일의 `held` 에 있다. 제목만 확인했거나 전후 수치를 원문에서 찾지 못한 것, 국회 통과를 확인하지 못한 개편안들이다.
- 원칙: 원문 본문을 열어 대조한 것만 올린다. 정부안과 발표 단계는 "정부안"으로 표시하고 확정된 것처럼 쓰지 않는다. 전망과 권유는 쓰지 않는다.

## 자료를 어떻게 유지하는가

- 자료는 저장소의 파일 하나다(구현 때 `frontend/js/policy-data.js` 로 옮기고 서버 페이지도 같은 파일을 읽는다). DB 를 쓰지 않아 요청마다 드는 비용이 없다.
- 검사가 항목마다 출처 주소, 확인일, 분류, 상태가 있는지 본다. 없으면 실패한다.
- 새 발표는 이미 도는 감지 작업이 알려 준다(health 의 `pendingReview`). 감지되면 원문을 열어 항목을 더하고 확인일을 고친다. 화면 맨 위에 마지막 확인일이 보이므로 오래되면 드러난다.
- 지금 화면의 타임라인(`POLICY_TIMELINE`)과 규제 요약 창의 "후속 정책" 줄은 이 자료에서 뽑아 쓰게 바꿔 두 벌이 되지 않게 한다.

## 꼭 다시 볼 것

- 서울 전역과 경기 12곳 토지거래허가구역은 2026년 12월 31일까지다. 연장 공고를 아직 찾지 못했다. 12월에 다시 확인한다.
- 2026년 세제개편안(종부세 기본공제 14억, 양도세 중과 한시 완화 등)은 정부안이다. 국회 통과 여부와 최종 내용을 확인해야 한다.
- 스트레스 DSR 의 2027년 이후 적용.

## 정해야 할 것(운영자)

- 분류 다섯 가지와 카드 구성이 이대로 좋은지.
- 공급 계획(몇 만 호 공급 같은 발표)을 넣을지. 권고는 넣되 "계획"으로 표시하고 기본 보기에서는 접어 두는 것이다. 사람들에게 바로 닿는 규제와 섞이면 길어진다.
- 외국인 대상 규제를 넣을지. 권고는 넣는 것이다(자료에 2건).

## 시안 확인과 구현 결과 (2026-11-16)

시안: https://claude.ai/design/p/630c0f3a-88f5-4245-aa88-9e7872eef676 . 위 표의 A~I 를 모두 그렸다. 화면으로 직접 본 것은 A(데스크톱, 모바일, 다크), B1~B6, C, D, I, G1, G2, H 데스크톱이다. G3(규제 요약 창의 단추)과 H 모바일은 캔버스에서 찾지 못해 보지 못했다. 둘은 구현한 뒤 로컬 미리보기의 실제 화면으로 확인했다.
시안에서 도구가 스스로 넣은 것: B4 의 "펼치기"와 "접기" 단추, C 화면의 카드가 한 장뿐인 것, D 화면의 조건. 구현에서는 "펼치기"와 "접기"만 그대로 쓰고 나머지는 자료대로 나온다.

만든 것
- 자료 원본 `backend/data/policy-changes.json`(38건). `node scripts/build-policy-data.js` 가 화면용 `frontend/js/policy-data.js` 를 만든다. 원본을 고치면 이 명령을 다시 실행한다(검사가 두 파일이 같은지 본다).
- 화면 `frontend/js/policy.js`(새 일반 스크립트, 본체를 키우지 않음)와 `frontend/index.html` 의 화면 틀, 스타일, 연결.
- 들어가는 길: 위쪽 도구 메뉴와 모바일 도구 목록의 "정책 변화", 대출 계산 화면의 "최근 정책 변화" 3건과 "전체 보기", 규제 요약 창의 "바뀐 내용 날짜순으로 보기", 주소 `?view=policy`.
- 서버 페이지 `/policy`(`backend/routes/policyPage.js`). DB 와 외부 API 를 부르지 않고 CDN 이 하루 기억한다. 사이트맵에 넣었다.
- 대출 계산 화면의 옛 타임라인 자료(`POLICY_TIMELINE`)는 자료 파일을 못 받았을 때만 쓰는 대체용으로 남겼다.

확인
- `npm run verify` 1,262개 통과. 회귀 검사 `backend/test/policy-changes-1116.test.js`(10개): 자료 모양, 잘못된 자료를 잡는지, 화면을 실제로 그려 카드 수와 조건 고르기와 글자 이스케이프, 서버 페이지.
- 로컬 미리보기: 카드 38장, 연도 구분, 세금과 예정·정부안을 고르면 3건, 결과 없음 안내, 계획 카드 펼치기, 끝난 카드 4장 흐림, 모바일 375 에서 가로 넘침 없음과 전후 칸 위아래, 다크 색, 들어가는 길 세 곳, 서버 페이지 데스크톱과 모바일.
- 확인하지 못한 것: 운영에서의 `/policy` 경로와 `/js/policy*.js`(배포 뒤 확인), 검색 엔진 수집.

자료를 고치는 절차
1. 새 발표가 감지되면(health 의 `pendingReview`) 원문 본문을 연다. 제목만 보고 쓰지 않는다.
2. `backend/data/policy-changes.json` 에 항목을 더하거나 고친다. 숫자와 표현은 원문에 있는 것만 쓴다. 정부안과 발표 단계는 status 를 "안"으로 두고 note 에 그 사실을 적는다.
3. 뒤 조치로 바뀐 옛 항목은 status 를 "종료"로 바꾸고 note 에 무엇으로 바뀌었는지 적는다.
4. 전체를 다시 대조했으면 `checked` 를 그날로 고친다. 일부만 봤으면 고치지 않는다.
5. `node scripts/build-policy-data.js` 를 실행하고 `npm run verify`.
