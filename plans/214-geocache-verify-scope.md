1. 측정 보강(코드 한 곳, 동작 그대로): 재확인 단계의 CPU 를 `process.cpuUsage()` 로 따로 재서 health 기록에 `verifyCpuMs` 로 남긴다. 하루 지나 이 값과 cpuMs 를 본다. 바꾼 뒤 줄어든 CPU 를 말할 근거가 이것이다.
2. 운영자가 A, B, C 중 고른다(A 면 30일과 7일 값도).
3. 고른 방안을 구현한다. 검사: 조회 조건이 source 별 기준을 쓰는지, LOCKED_SOURCES 를 건드리지 않는지, 대상 0행이면 바로 끝나는지(가짜 DB 로).
4. 배포 뒤 이틀 동안 health 의 verifyRows, verifyFixed, verifyMs, verifyCpuMs, cpuMs 를 전과 견준다. `apt_geocache` 의 source 별 행 수가 크게 바뀌지 않았는지(조회만) 본다.
