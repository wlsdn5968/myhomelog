## 왜 중요한가

운영자가 챗에서 겪은 실패와 **같은 원인**이 검색창에도 있다. `backend/routes/search.js:170-172`:

```js
  //   가드: 제거 후 2자 미만이면 원본 유지("아파트"만 입력 시 전체매칭 방지).
  const _qStrip = q.replace(/\s*아파트(?:단지\)?\s*$/, '').trim();
  const qApt = _qStrip.length >= 2 ? _qStrip : q;
```

⚠ 위 발췌의 정규식은 **문서 표기상 깨져 있을 수 있다 — 반드시 실제 파일을 읽어 확인하라.**
요점은 **끝의 "아파트" 접미사만 제거하고 문자열 중간의 공백은 그대로 둔다**는 것이다.

`qApt` 는 그대로 세 곳의 `ILIKE '%…%'` 에 들어간다(`search.js:207-215`):
`molit_apt_index.apt_name` · `apt_master.apt_name` · (`q` 원문으로) `apt_master.umd_nm`.

### 실측 (프로덕션 DB, 2026-09-06)

| 측정 | 값 |
|---|---|
| `molit_apt_index` 이름 22,473개 중 **공백 포함** | **189 (0.8%)** |
| `apt_master` 이름 14,661개 중 **공백 포함** | **2,251 (15.4%)** |
| 질의 공백 제거만으로 추가로 도달 가능해지는 단지 | **+589** |

**비대칭이 원인이다.** 사용자는 앱에 표시된 정식명(15.4%가 공백 포함)이나 "지역 단지명" 형태로
입력하는데, MOLIT 이름은 99.2%가 공백이 없다. 그래서 `%공릉 풍림아이원%` 는 원리적으로 0건이다.

## 단계

### Step 1: 공백 제거 변형을 **추가** 조회로 넣는다 (기존 조회는 유지)

`qApt` 를 **바꾸지 마라.** 공백 든 이름 189 + 2,251 개가 기존 경로에서만 잡힌다.
대신 `_qNo = qApt.replace(/\s+/g, '')` 를 만들고, `_qNo !== qApt` 일 때만 조회를 **추가**한다:

- `molit_apt_index.apt_name ILIKE '%_qNo%'` 1개
- `apt_master.apt_name ILIKE '%_qNo%'` 1개

⚠ `_qNo.length < 2` 면 추가하지 마라(전체매칭 방지 — 기존 가드와 같은 취지).
⚠ 기존 `_softQuery(...)` 래퍼와 **같은 방식**으로 감싸라. 이 저장소는 부분 실패를 강등으로
처리하는 규약이 있다(`search.js:239-292`). 새 조회의 실패가 **500 을 만들면 안 된다** —
실패해도 기존 결과만으로 응답이 나가야 한다.

**검증**: `node --check backend/routes/search.js` → exit 0

### Step 2: 캐시 키를 반드시 바꾼다 ⚠

`search.js:176` 이 결과를 캐시한다:

```js
  const sck = `searchapt:${q.toLowerCase()}:${limit}`;
```

그리고 `SEARCH_CDN = 'public, s-maxage=600, stale-while-revalidate=3600'` 로 **엣지에도** 캐시된다.

키에 버전 성분이 없다. **버전 성분을 추가하라**(예: `searchapt:v2:…`).
안 바꾸면 옛 결과(공백 질의 = 빈 목록)가 캐시 수명만큼 계속 서빙된다.
이 저장소는 **열화된 응답이 엣지에 6시간 굳어 지역 선택기가 통째로 사라진** 실사고가 있다.

⚠ 엣지 캐시는 URL 기준이라 서버 키 변경으로 비워지지 않는다. 배포 후 최대 10분(`s-maxage=600`)
동안 옛 응답이 나올 수 있다 — **그 사실을 보고에 적어라.** 라이브 확인은 그 시간 이후에 하라.

**검증**: `grep -n "searchapt:" backend/routes/search.js` 로 키가 바뀐 것을 보여라.

### Step 3: 결과 병합에서 중복이 생기지 않는지 확인한다

새 조회는 기존 조회와 **결과가 겹친다.** 병합 지점(`molitRows` 구성, `apt_master` 보충)에서
같은 단지가 두 번 나오면 자동완성에 중복 항목이 뜬다.
기존 그룹핑 키를 **그대로 사용**해 중복이 흡수되는지 **직접 읽고 확인**하라.
흡수되지 않으면 병합 전에 행 고유키(`apt_name|lawd_cd|sigungu|umd_nm|build_year`)로 중복을 제거하라.

**검증**: 새 조회를 넣기 전/후로 같은 질의의 결과 개수를 비교하는 테스트를 쓰라.

### Step 4: 테스트

`backend/test/characterization.test.js` 끝에 추가:
