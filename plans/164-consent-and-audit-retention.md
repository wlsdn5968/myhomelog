## 2. 결정할 것

**A. 익명 동의 기록을 얼마나 보관할지**
- A1 지금대로 영구 보관 + 처리방침에 항목 추가(가장 보수적).
- A2 보관 기간을 정해 그 뒤 삭제(예: 회원 탈퇴 시까지가 아니라 익명이라 기간 기준) — `auditPrune.js`·`prune_audit_log` 목록을 함께 고쳐야 한다.
- A3 로그인 성공 뒤 회원 ID 와 묶어 한 번 더 기록하고, 익명 행은 짧게(예: 90일) — 증빙이 실제 회원과 연결된다. 코드 변경 필요(프런트 로그인 완료 처리 + 서버 인증 라우트).

**B. 처리방침 153행 "접근 기록 1년 이상" vs 코드 90일 삭제**
- B1 코드를 처리방침에 맞춰 일반 기록 보관을 1년 이상으로(`AUDIT_LOG_RETENTION_DAYS` 환경변수 또는 기본값). DB 용량 영향: 현재 audit_log 전체 80 kB 라 미미.
- B2 처리방침 문구를 실제와 맞게 고침.

## 3. 권고 (제 판단 — 법적 확인 전 임시)
- 지금 코드는 바꾸지 않는다(증빙을 줄이는 쪽 변경은 되돌릴 수 없다).
