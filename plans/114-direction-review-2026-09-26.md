## 2. 장기 방향 — 제안 (효과÷비용 순 · 전부 무료 · 오버 금지)

> 각 항목: **무엇을** / **어떻게 도입** / **왜 좋아지나(근거)** / **비용·위험** / **UI 절차**. "추정" 표기가 없는 효과는 코드·실측에서 직접 따라간 것이다.

### P1. 공개 페이지 → 앱 **맥락 유지 딥링크** (F1) — P0 · S · UI 변경 없음
- **어떻게**: `aptPage.js:479` 의 CTA 를 `${ORIGIN}/?apt=${encodeURIComponent(aptName)}&area=${encodeURIComponent(sigungu)}` 로. `handleShareUrl()` 이 이미 이 파라미터로 상세를 연다(공유 링크와 같은 경로 = 검증된 경로). `/region/:lawdCd` 의 "단지 검색·대출 계산 →" 는 SPA 가 지역 파라미터를 받는지 **미확인** → 계획 단계에서 `index.html` 의 `URLSearchParams` 처리 8곳을 확인해 지원되면 같이, 아니면 단지 CTA 만.
- **왜**: 조직적 유입은 지금 2건 수준이지만 **유일한 무료 유입면**이 15,954 페이지다. 그 페이지의 첫 클릭이 맥락을 버리면 나머지 제품이 아무리 좋아도 소용없다. 이건 기능 추가가 아니라 **이미 있는 두 조각을 잇는 한 줄**이다.
- **비용·위험**: 코드 1~2줄 + 테스트 1건. 위험 낮음(딥링크 경로는 `/share` 가 매일 쓰는 경로).
- **검증**: 배포 후 `/apt/43114-58` 의 CTA href 가 `?apt=신동아아파트&area=청주시 청원구` 이고, 그 URL 로 들어가면 상세 모달이 열리는지 `get_page_text` 로 확인.

### P2. 랜딩 히어로를 **실데이터**로 (F2) — P1 · S~M · **시안 먼저**
- **어떻게**: "예시" 차트·"예시 60/100" 블록을 제거하고, 그 자리에 **바로 옆 TOP 카드의 1위 단지(오늘 벽적골우성)의 실제 24개월 가격 흐름**을 그린다. 데이터는 이미 두 경로가 있다 — 상세 모달의 추이 차트(Plan 102 `/api/transactions/history`)와 TOP 카드가 이미 받아둔 단지 정보. 새 API·새 테이블 없음. 캡션은 "실거래 · 국토부 신고 · 참고용" + 기존 disclaimer 유지.
- **왜**: 첫 화면의 약속이 "객관적 데이터" 인데 첫 그림이 가짜다. 사용자 0명인 제품에서 첫 화면은 제품 전체다. 실데이터로 바꾸면 **추가 설득 문구 없이** 데이터 자산(477K)이 스스로 증명한다. Plan 083 이 "5Y 차트 허위 약속" 을 지운 것과 같은 원칙의 연장.
- **비용·위험**: 프론트 1개 블록 교체. 위험: 1위 단지가 바뀌면 그림도 바뀐다(의도) · 거래가 적은 단지가 1위가 되면 선이 빈약할 수 있음 → "최근 24개월 거래 N건 이상" 조건으로 폴백 단지 선택(TRUST 게이트 원칙과 같은 방향).
- **UI 절차**: 운영자 룰대로 **claude.ai/design 시안** → 검토 → 구현. 시안 범위는 히어로 우측 카드 1장으로 좁게(IA 재편 아님).

### P3. `dataSyncedAt` 회귀 (F3) — P0 · S · **진행 중(Plan 113)**
소스를 `molit_ingest_runs.finished_at` 으로, null 은 60초만 캐시, Redis 오염분 미스 처리. 배포 후 "LAST SYNC" 가 날짜로 돌아온다.

### P4. 사실과 다른 문구 4건 정리 (F4) — P1 · XS×4 · UI 변경 없음(문구만)
- ① "AI 특약 초안" → "표준 특약 초안(규제·연식·특이사항 반영 템플릿)" 으로, AI 환각 disclaimer 는 **AI 를 실제로 쓰는 곳에만**. 근거: `clause.js` 는 로컬 템플릿, LLM 0회(09-16 실측). 지금 문구는 없는 위험을 경고하고 없는 능력을 주장한다.
- ② "2025.05 이후" → `/api/health` 나 `aptHistoryService` 의 `since` 로 동적 렌더(107 부록 A2-4).
- ③ `billing_plans.free.features` 의 "월 1회" → 코드와 같은 "하루 1회" (DB 1행 UPDATE, 운영자 승인). ⚠ 이건 **문구 정확성**만 다룬다 — 결제·플랜 정책은 운영자 영역이라 제안하지 않는다.
- ④ 지역 페이지 "확인 필요" → "**고시된 규제지역 목록에 없음** · 기준 {snapshot 검증일}" — 여전히 단정하지 않지만 결손처럼 읽히지 않는다(`region.js:135` 문자열 1개 + 기준일 전달).
- **왜**: 이 제품의 포지셔닝 전체가 "정직한 데이터" 다. 문구 하나가 그걸 깎는다.

### P5. 모바일에서 도구 3종 도달 경로 (F5) — P2 · S · **시안 먼저**
- **어떻게**: 하단 탭 5번째 "대출" 을 "**도구**" 로 바꾸고 탭하면 바텀시트(대출계산·특약·청약·규제 요약 4항목). 데스크톱 "도구 ▾" 드롭다운과 **같은 목록·같은 순서**라 새 정보구조가 아니다. 대안: 햄버거 드로어에 "도구" 섹션 추가(더 싸지만 발견성 낮음).
- **왜**: 특약·청약은 각각 완성된 뷰(가점 계산기 84점·표준 특약)인데 모바일에선 진입점이 없다. 기기 비율은 **측정 불가**(Vercel Analytics 미설정)라 "모바일이 다수" 라고 **주장하지 않는다** — 다만 조직적 유입의 첫 기기가 모바일일 가능성은 일반론이 아니라 공개 페이지가 SEO 표면이라는 사실에서 나온다.
- **비용·위험**: 프론트 바텀시트 1개. 07-19 모바일 UX 기획(M-A~M-D)이 이미 "데스크톱과 달라도 되니 깔끔하게" 를 운영자 지시로 기록해 뒀다 — 그 연장선.
- **UI 절차**: 시안 먼저(375×812 1장).

### P6. 이력 전용 5,475단지 이름 복구 = 공개 페이지 +34% (F6, 107a-2) — P1 · M · **운영자 결정 대기**
- **어떻게**: `molit_hist_runs` 에 기록된 7,000개 (지역,월) 쌍을 MOLIT API 로 **다시 조회해 `aptSeq → aptNm` 만** `molit_apt_dim` 에 채운다(행당 ≈60B → +0.3MB). Hobby cron 일일 슬롯에 분산(하루 700콜 × 10일 추정). 페이지 렌더는 107a 가 이미 배선했으므로 이름만 채우면 404 → 200 으로 바뀐다.
- **왜**: 사이트맵 15,954 → ≈21,400 페이지. 새 데이터가 아니라 **이미 가진 30,962건의 거래를 처음으로 보여주는 것**. 무료 API, 저장 0.3MB.
- **비용·위험**: cron 1개 + 슬롯 10일. 위험: 2020~2024 에 거래가 끝난 단지 페이지라 "최근 24개월" 요약이 비어 **이력 차트만 있는 페이지**가 된다 → 페이지 템플릿에 "최근 거래 없음 · 2020~2024 이력 N건" 분기가 필요(값 지어내지 않기).

### P7. (후보 · 근거 약함) 보고서 입력 **페르소나 프리셋** — P3 · S · 시안 먼저
집사닷컴 실측에서 배울 것으로 적어둔 항목(9종 프리셋으로 입력 채우기). 우리 보고서 입력은 3단계 7항목이라 프리셋 5~6개(생애최초·갈아타기·신혼·1주택 추가·현금 위주)로 **한 번의 탭에 7항목**을 채울 수 있다. 무료·소형. **다만 사용자 0명이라 효과를 측정할 수 없다** — P1~P6 뒤에, 그리고 보고서 진입 데이터가 생긴 뒤에 판단.
