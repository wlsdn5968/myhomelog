## 6. 고쳐도 되돌아오는 이유 (코드·DB 원문 확인)
1. 매주 월 20:00 UTC `aptMasterSync` → `refresh_molit_aliases()`: 규칙으로 다시 계산한 별칭 배열로 **통째 교체**(`SET molit_aliases = agg.aliases … IS DISTINCT FROM`, 운영 DB 함수 본문 확인, 'manual' 처리 없음). 손으로 넣은 별칭은 그 단지가 규칙 결과에 잡히면 지워지고, 손으로 뺀 잘못된 별칭(예: §3)은 다시 들어간다.
2. 같은 주간 작업이 `apt_master.apt_name·sigungu·umd_nm` 을 KAPT 값으로 덮어쓴다(aptMasterSync.js:179).
3. 매일 04:00 UTC `geocache-backfill` 주소 검증: 저장 주소 본번이 신고 지번과 다르거나 300m 초과면 좌표를 덮어쓴다(geocacheBackfill.js:290~300). 손 수정 보호 표시 없음(grep). 좌표 캐시 전부가 10-22~10-30 사이에 다시 쓰였다(cached_at).
4. 한 단지의 이름·합치기를 화면마다 따로 계산한다(별칭 사용 화면 7곳·미사용 3곳). 이력(작업 노트): 공릉풍림만 05-12~10-30 사이 8번 이상, 매번 다른 화면을 고쳤다.
5. 저장소 기준 스키마 `supabase/schema.sql:880` 의 별칭 함수가 옛 판(tie·tjb·sbase 규칙 0개) — 이 파일로 복구하면 옛 규칙으로 돌아간다.
6. 캐시(코드 조사 기준): 인기 스냅샷 36시간·장애 시 7일, 구별 TOP10 36시간, 별칭 맵 1시간, 검색 10분 + CDN.
