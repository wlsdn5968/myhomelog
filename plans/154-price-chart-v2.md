## 0. 지금 문제 (코드 원문 `frontend/index.html` `renderPriceChart`)
- SVG 320×120, 글자 9px, 세로축 값 2개(최소·최대), 월 단순평균 선 하나.
- 개별 거래·최고·최저 표시 없음, 아래 줄은 "첫 달 대비 변화"뿐.

## 1. 바꿀 것 (시안 확정 뒤 값 반영)
1. 맨 위 한 문장(해요체): "{평형}가 최근 {X}억에 거래됐어요. {기간} 중 최고 {H}억, 최저 {L}억이에요."
2. 숫자 칸 3개: 최근 거래 / 기간 최고 / 기간 최저(각 날짜·층). **최고는 항상 최저와 함께**(절대 룰 ①).
3. 기간 칩 1년·3년·전체 + 기존 평형 칩 재사용.
4. 차트: 점 = 거래 1건, 선 = 3개월 중앙값(앞뒤 1개월 포함), 최고·최저·최근 3점만 강조·라벨, 세로축 0.5억 눈금(12px), 가로축 연도(1년은 분기).
5. 점 누르면 날짜·층·금액. 키보드 접근(점에 `<title>` + 포커스) 검토.
6. 출처 줄: 국토교통부 실거래가 · 같은 단지·같은 면적 · 층·향 보정 없음 · 매수·매도 추천이 아니에요.

## 2. 데이터 (지어내지 않는다)
- 1년·3년: 원본 `/api/transactions`(최대 15개월) + 이력 `/api/transactions/history`(Plan 102, `_curTrendLong`) 를 합친 개별 거래.
- **실측(2026-10-29)**: `/api/transactions/history` 는 `getAptHistoryMonthly` — (월, ㎡)별 **합계만** 준다. 개별 점·정확한 최고/최저를 못 그린다.
  → 새 경로 필요: `molit_transactions_hist`(apt_seq, deal_date, exclu_use_ar×100, deal_amount, floor — 거래 단위 행)에서
  단지·평형(±2㎡)별 개별 거래를 service_role 로 읽는 `/api/transactions/history-deals?aptSeq=&area=`(상한·캐시 6h, 공개 키 노출면 늘리지 않음).
  최고·최저는 원본+이력 개별 거래로 계산(경신 기준선 `molit_hist_peaks` 와 같은 정의인지 대조).
- 해제 거래 제외(적재 단계에서 이미 제외 — `molitIngest` cdealType).
- 거래 2건 미만이면 차트 대신 "거래가 적어 그래프를 그리지 않아요" 문구.
